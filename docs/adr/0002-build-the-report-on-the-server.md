# 現調報告書の PDF はサーバーで組み立て、完成プレビューは同じ割り付けから作った HTML で見せる

日本語を PDF に埋め込むにはフォントが要る。この環境で使える IPAゴシックは 6.2MB、
圧縮しても 4.3MB あり、端末側で組み立てる形にすると担当者の回線でこれを落とすことになる。
現場の回線でこれは重い。そこでフォントはサーバーに置き、PDF はサーバーで組み立てる。

送付は「完了」の1回の通信で、写真と文字を送り、サーバーが組み立てて会社へメールする。
組み立てと送付を分けると、PDF を落として送り直す往復が増え、電波の弱い現場で失敗が増える。

完成プレビューは PDF そのものではなく、HTML で見せる。PDF を見るにはサーバーへ写真を
送って返してもらう必要があり、送付前にもう1往復増えるため。

## Consequences

- プレビューと PDF が食い違わないよう、**どのページに何が載るかを決める割り付けは1つの
  純粋なモジュール（`src/report/layout.ts`）に置き、HTML と PDF の双方がそれを読む。**
  ページ数と並び順はここで決まり、単体テストで確かめる。
- 文字の見た目（字体・行の折り返し）までは一致しない。一致するのは「何が何ページ目に
  どの順で載るか」まで。
- 容量の上限は、PDF ではなく**送り出す写真と文字の合計**にかかる（Vercel の本文上限 4.5MB）。
- サーバーの処理にフォントの読み込みが入るため、送付は一瞬では終わらない。
  画面に送付中であることを出す必要がある。
